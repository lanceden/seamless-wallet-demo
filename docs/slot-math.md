# 老虎機數學（Slot.Core）

對應 `SLOT_PLAN.md` §5。所有數字都可以用下面的指令重現；原始輸出在 [`docs/slot/rtp-report.txt`](slot/rtp-report.txt)。

```bash
dotnet run --project src/Slot.RtpSimulator -c Release -- --spins 10000000 --seed-free
```

## 1. 規則

- 5 軸 × 3 列，固定 **10 條連線**；下注 = 每線下注 × 10。連線形狀見 `Paylines.cs`（1 中、2 上、3 下、4 V、5 倒 V、6 下斜、7 上斜，8～10 為折線）。
- 由左至右連續 **3 個以上**相同符號才算中獎，**一條線最多一筆**（只算最高連數）。
- **WILD 替代所有一般符號**，只會出現在第 2～4 軸。一條線的中獎符號是線上第一個非 WILD 符號，開頭的 WILD 都算進連數（`WILD WILD BAR BAR BAR` = BAR × 5）。整條都是 WILD 沒有賠率 → 不中獎（WILD 不在賠率表）。
- 盤面：RNG 對每軸選一個停止位置，取連續 3 格（環狀）。RNG 是 `RandomNumberGenerator.GetInt32`（`SecureRandomSource`），不用 `System.Random`。
- 結果完全由伺服器決定；`SlotEngine.Spin(lineBet)` 回傳 `Stops`、`Reels[軸][列]`、`Wins[]`、`TotalBet`、`TotalWin`。符號代碼（API 用）：`WILD 7 BAR BELL MELON CHERRY LEMON`。

## 5. 調整過程

1. **起點：SLOT_PLAN §5.2 的示意賠率**（7 為 20/100/500…檸檬 1/4/12）配上一組手排轉輪帶：**RTP 只有 35.2%**，中獎率 53.6%，最大單局只有 57×。示意賠率拿來配這個符號分布，返還率遠低於目標。
2. **一個讓調整變容易的性質**：停止位置是均勻的，所以任一條線在每一軸看到某個符號的機率就等於「該符號在該軸的格數比例」，各軸獨立。因此 **RTP 只由「各軸的符號格數」和「賠率表」決定，與符號在轉輪帶上的排列順序無關**（`RtpCalculator.Analytic`，測試 `Rtp_does_not_depend_on_the_order_of_symbols_on_a_strip` 鎖住這件事）。調參時不必每次列舉 3,355 萬組，列舉 7⁵ = 16,807 種符號組合即可。排列順序只影響中獎的分布與觀感，所以用 `StripBuilder` 把同一種符號等距分散。
3. **調參器**（`Tuner`，退火搜尋、固定 seed 可重現）：移動單位是「某一軸把 1 格從符號 A 改成 B」與「把某個賠率乘以 0.8～1.5 倍」。
   - 目標：RTP = 96%、中獎率 = 32%（用蒙地卡羅估計，因為排列會影響它）。
   - 約束：高分符號的格數不多於低分符號、賠率不低於低分符號、每個一般符號每軸至少 1 格、WILD 只在第 2～4 軸（各至少 1 格）、同一符號連數越多賠越多。
   - 代價函數：RTP 偏差每 0.2% 扣 1 分、中獎率偏差每 1% 扣 1 分、再加上「相鄰連數倍數超過 4 倍」的賠率曲線懲罰（第一次沒有這項，調出 3 連 25 倍 → 4 連 218 倍的斷崖賠率）。
   - 指令：`dotnet run --project src/Slot.RtpSimulator -c Release -- --tune --iterations 8000 --target-hit 0.32 --tune-seed 1`
4. **結果**：RTP 收斂到 95.995%。試了 3 個 seed 都收斂在 96.0%，但**中獎率都停在 53%～56%，沒有降到目標的 32%**；採用賠率曲線最平滑的 seed 1。

### 為什麼中獎率下不來（誠實的取捨）

這是這個設計的結構性結果，不是調參失敗：目前沒有 Free Spin、Bonus、Jackpot 等功能玩法，**RTP 的 96% 全部要靠連線支付**。每條線只有 6 種一般符號，要在不靠大獎的情況下付得起 96%，就必須讓小獎頻繁出現；想壓低中獎率就得讓大獎賠率變得很誇張（在我試過的 3 個 seed、8,000 次迭代的設定下，調參器沒有找到兼顧自然賠率曲線與低中獎率的解；這不是窮盡搜尋的結論）。真實機台的 25%～35% 中獎率通常有一部分返還來自功能玩法。

要降低中獎率，方向是加入功能玩法（SLOT_PLAN 的加分項：Scatter 觸發 Free Spin），把一部分 RTP 移到低頻高額的功能裡，再重新調參。

## 6. 測試

- `tests/Slot.Tests`（57 項）：連線、WILD、只算最高連數、盤面環狀視窗、RNG 範圍與均勻度、設定驗證、RTP 計算（含「列舉 = 解析式」「排列不影響 RTP」）、模擬器（可重現、快速路徑 = 引擎路徑、蒙地卡羅 vs 列舉在 4σ 內）、調參器（約束、確定性、RTP 明顯靠近目標），以及**正式設定的 RTP 必須在 95%～97%**。
- 快速路徑（`LineEvaluator.TotalMultiplier`、模擬器）與詳細路徑（`Evaluate`、`SlotEngine.Spin`）共用同一個單線算分函式，並有 5,000 個隨機盤面的一致性測試。
